## 2) Data Preprocessing and Labeling

Implemented in: [HLC/src/datasets.py](HLC/src/datasets.py)

- Identifier columns to drop (tentative defaults, safe across datasets):
  - Flow/packet IDs and raw network identifiers such as:
    - Flow ID, Src IP, Dst IP, Timestamp, saddr, daddr, id.orig_h, id.resp_h, uid, frame.time
- Label-column auto-detection (tries common names): Label, label, Attack_type, Attack_label, attack, category, subcategory
- Non-numeric encoding: non-numeric columns are string-cast and label-encoded
- Scaling: StandardScaler (persisted as scaler.joblib per split)
- Splitting: stratified train/test; files persisted under data/processed/<DATASET>_<binary|multiclass>/

Classification setting:
- All datasets are treated as classification (binary or multiclass), as requested.
- Binary vs. multiclass is inferred by number of unique labels in y (or prompted via CLI before split/visualization/training, per workflow).

## 3) Model

Defined in: [HLC/src/models.py](HLC/src/models.py)

- Parallel CNN+LSTM fusion encoder:
  - CNN path learns local feature correlations
  - LSTM path captures sequential/context dynamics
  - Concatenation → dense → dropout → output logits
- Baseline: lightweight MLP for comparison
- Training defaults:
  - Optimizer: AdamW (weight_decay=1e-4)
  - Loss: CrossEntropy
  - Batch size: 256
  - LR: 1e-3
  - Early stopping patience: 8
  - Epochs: 50–100
- Outputs:
  - Checkpoints (.pt)
  - history.csv
  - learning_curve.eps
  - complexity.json (params + estimated MACs per-sample)
  - efficiency.json (timings and energy proxy)

Generated by: [HLC/src/train.py](HLC/src/train.py) and plotting utilities.

- Plots training and validation loss versus epochs (learning_curve.eps)
- Overfitting: training loss ↓ while validation loss ↑

## 10) CLI Workflow

Primary entrypoint: [HLC/main.py](HLC/main.py)

Interactive menu (automation via argparse also available):
1) Load & split dataset (persist)
   - Choose dataset (EDGE_IIoT, CIC-IoT-2023, Apose-IoT-23, CIC-IIoT-2025, CIC-IoMT-2024, optional CIC-IoT-IDAD-2024)
   - Choose classification type (binary|multiclass)
   - Split → saves to data/processed/<DATASET>_<binary|multiclass>/
2) Load existing split
   - Select from data/processed list (no timestamps, stable prefix)
3) Visualize features (EPS)
   - Choose raw dataset or processed split
   - Outputs saved to outputs/<DATASET>_<binary|multiclass>/viz/
4) Train model
   - Choose split
   - Choose model (fusion|mlp), epochs, batch size, LR, patience
   - Saves checkpoint, learning curve, history.csv, complexity.json, efficiency.json
5) Evaluate & plot performance
   - Finds latest checkpoint under checks/
   - Writes metrics JSON/CSV, confusion matrix, ROC/PR curves under eval/
6) XAI (SHAP/LIME/ANOVA)
   - Uses trained checkpoint to generate XAI outputs under xai/
7) Ablation (user-selected features)
   - Prompts for a list of features to keep
   - Retrains and compares performance
8) Inference (load saved model and run on new data)
   - Persist y_pred.npy and y_proba.npy (if applicable) under inference/

Automation examples (argparse):
- Split:
  - python HLC/main.py split --dataset EDGE_IIoT --class_type binary --test_size 0.2 --seed 42
- Train:
  - python HLC/main.py train --split_key EDGE_IIoT_binary --model fusion --epochs 60 --batch 256
- Evaluate:
  - python HLC/main.py eval --split_key EDGE_IIoT_binary
- XAI:
  - python HLC/main.py xai --split_key EDGE_IIoT_binary --methods shap,lime,anova
- Ablation:
  - python HLC/main.py ablate --split_key EDGE_IIoT_binary --keep_feats "Duration,Rate,Srate,Drate,syn_flag_number,ack_flag_number"
- Inference:
  - python HLC/main.py infer --split_key EDGE_IIoT_binary --csv data/new/live_batch.csv

Note: The code will be aligned to ensure no timestamps are appended to split/output folder names, satisfying this spec.

## 12) Experimental Protocol (Recommended Defaults)

- n_seeds = 5: {13, 23, 33, 43, 53}
- Train each dataset in binary and/or multiclass modes as applicable:
  - EDGE_IIoT: binary (Normal vs Attack) and multiclass (attack families)
  - CIC-IoT-2023: binary + multiclass
  - Aposemat IoT-23: multiclass recommended (many malware families)
  - CIC-IIoT-2025: binary + multiclass depending on label granularity
  - CIC-IoMT-2024: binary + multiclass (MQTT-specific attacks)
- For each configuration:
  1) Split and persist processed data
  2) Visualize distributions (EPS)
  3) Train (fusion and baseline)
  4) Evaluate and collect metrics/plots
  5) Run XAI suite
  6) Run ablation on top-k SHAP/LIME features
  7) Aggregate n=5 seeds to seed_stats.json (mean±std)
  8) Record complexity.json, efficiency.json
  9) Save best checkpoint for deployment
